# FacePanel — распознавание лиц и учёт посещений

Камера на проходной узнаёт человека, панель записывает проход, показывает его
на экране КПП в реальном времени и, если подключено реле, открывает турникет.

Система состоит из двух частей, которые работают на одной машине:

| Часть | Что делает | Технологии |
|---|---|---|
| **Панель** (корень репозитория) | веб-интерфейс, REST API, база, живые обновления | Java 21, Spring Boot 3.5, PostgreSQL, Thymeleaf, WebSocket/STOMP |
| **Клиент камеры** (`OpenCVRework/`) | читает видео, находит и узнаёт лица, шлёт события в панель | Python 3, OpenCV (YuNet + SFace) |

```
IP-камера / веб-камера
        │ видео
        ▼
клиент камеры (face_2.py, по процессу на камеру)
        │ POST /api/v1/recognitions          ──►  ESP-реле турникета (необязательно)
        ▼
панель :8080  ──►  PostgreSQL
        │ WebSocket
        ▼
браузеры: экран КПП на планшете, дашборд оператора
```

Панель и клиент должны лежать в одной копии репозитория: клиент считает
эмбеддинги по фотографиям из общей папки `faces/`, куда их кладёт панель.

## Быстрый старт

Ниже — запуск на одном компьютере для разработки или демонстрации. Команды даны
для Windows (PowerShell); на Linux и macOS отличия указаны в конце раздела.

### Что установить

| Программа | Зачем | Установка в Windows |
|---|---|---|
| Git | скачать репозиторий | `winget install Git.Git` |
| JDK 21 | собрать и запустить панель | `winget install EclipseAdoptium.Temurin.21.JDK` |
| Python 3.12 | клиент камеры | `winget install Python.Python.3.12` |
| Docker Desktop | PostgreSQL в контейнере | `winget install Docker.DockerDesktop` |

После установки закройте и заново откройте PowerShell, иначе новые команды не найдутся.

### 1. Репозиторий и база

```powershell
git clone https://github.com/fffoke/FaceID.git
cd FaceID
docker compose up -d
```

`docker-compose.yml` поднимает PostgreSQL с теми же именем базы, пользователем
и паролем, что прописаны в `application.properties`. Таблицы панель создаст сама
при первом запуске.

### 2. Панель

```powershell
.\mvnw.cmd package -DskipTests
java -jar target\operator-panel-0.0.1-SNAPSHOT.jar
```

Запускать нужно из корня репозитория — папка `faces/` создаётся относительно
текущего каталога. Панель готова, когда в логе появится `Started OperatorPanelApplication`.
Откройте <http://localhost:8080> и войдите через кнопку «Войти»
(учётная запись задана в `SecurityConfig.java`).

### 3. Люди и камера

1. `/persons` — добавьте человека и загрузите его фото (лицо анфас, хорошо освещено).
2. `/cameras` — добавьте камеру. Имя может быть любым, например `КПП 1`; панель
   сама построит латинский **slug** (`kpp_1`) — он показан в списке камер
   (метка `slug: …`) и нужен для запуска клиента.
   - IP-камера: впишите её RTSP-адрес в поле «Camera URL».
   - Веб-камера ноутбука: поле «Camera URL» оставьте пустым.
   - Адрес ESP-реле необязателен: без него камера только распознаёт и пишет журнал.

### 4. Клиент камеры

Во втором окне PowerShell:

```powershell
cd FaceID\OpenCVRework
python -m venv venv
venv\Scripts\pip install -r req.txt
$env:PYTHONIOENCODING = "utf-8"

# IP-камера (адрес берётся из реестра панели)
venv\Scripts\python face_2.py --camera-name kpp_1 --no-window

# либо веб-камера ноутбука
venv\Scripts\python face_2.py --camera-name kpp_1 --camera-index 0 --no-window
```

`--camera-name` — это slug камеры из `/cameras`. На каждую камеру запускается
свой процесс в своём окне. `PYTHONIOENCODING` обязателен в Windows: клиент пишет
в лог символы, которых нет в стандартной кодировке консоли, и без этой переменной
падает на первой же строке.

Откройте <http://localhost:8080/kpp> — должно появиться видео с камеры, а при
распознавании лица — запись в ленте справа.

### 5. Доступ с других устройств

Планшет или телефон в той же сети открывает `http://<IP компьютера>:8080`.
IP смотрите командой `ipconfig` (строка «IPv4-адрес» у активного адаптера).
Наружу нужен только порт 8080: видео с камер панель проксирует сама.

Брандмауэр Windows по умолчанию входящие подключения не пропускает. Разрешите
порт один раз, в PowerShell **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "FacePanel 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

### Повторный запуск

После перезагрузки компьютера: дождаться запуска Docker Desktop (база стартует
сама), затем `java -jar ...` из шага 2 и клиент камеры из шага 4. Собирать панель
и ставить зависимости заново не нужно.

### Linux и macOS

То же самое с поправкой на синтаксис: `./mvnw package -DskipTests`,
`venv/bin/pip`, `venv/bin/python`. Переменная `PYTHONIOENCODING` не нужна.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Панель падает с `Connection refused` на порту 5432 | База не запущена: откройте Docker Desktop, выполните `docker compose up -d`, проверьте `docker compose ps` |
| `Port 8080 was already in use` | Панель уже запущена в другом окне, либо порт занят другой программой |
| Клиент падает с `UnicodeEncodeError` | Не задана `$env:PYTHONIOENCODING = "utf-8"` в этом окне PowerShell |
| Клиент пишет «Камера не найдена в реестре» | В `--camera-name` указан не slug. Точное значение — метка `slug: …` на `/cameras` |
| Клиент пишет «Камера не открылась» | Неверный RTSP-адрес или камера недоступна по сети. Проверьте адрес в VLC: «Медиа → Открыть URL». Для веб-камеры попробуйте `--camera-index 1` |
| Видео на `/kpp` нет, а распознавание работает | Клиент запущен до того, как камеру добавили или изменили в панели, — перезапустите его |
| Человека не узнаёт | Нет фото или лицо на нём не найдено — в логе клиента будет строка про этого человека. Замените фото. Порог схожести — `threshold` в `OpenCVRework/settings.json` (меньше — мягче) |
| С планшета страница не открывается, с самого компьютера открывается | Не добавлено правило брандмауэра, либо планшет в другой сети, либо на точке доступа включена изоляция клиентов |
| Лица и база пусты после `git clone` | Так и должно быть: фото людей (`faces/`) — биометрия и в репозиторий не попадают |

## Страницы

Открыты без входа:

- `/`, `/kpp` — все камеры на одном экране и общая лента распознаваний
- `/kpp/{slug}` — экран одной камеры (для планшета на проходной)

После входа:

- `/dashboard` — живой журнал распознаваний
- `/session` — мероприятия: начать, завершить, история
- `/persons` — люди, фото, массовый импорт из ZIP
- `/attendance` — история посещений с фильтром по датам
- `/statistics` — аналитика и выгрузка в CSV
- `/cameras` — реестр камер

## Настройка

| Что | Где |
|---|---|
| Порт панели, подключение к базе, папка с фото | `src/main/resources/application.properties` |
| Адрес камеры, реле турникета | страница `/cameras` (клиент забирает их с сервера при старте) |
| Порог схожести, частота кадров, адреса API панели | `OpenCVRework/settings.json` |

Любой параметр `application.properties` можно переопределить без пересборки,
например: `java -jar target\operator-panel-0.0.1-SNAPSHOT.jar --server.port=9090`.

## Постоянная установка на сервере

На Linux-сервере панель и камеры работают как сервисы systemd: `face-supervisor`
раз в 30 секунд сверяется с реестром камер и сам запускает, перезапускает и
останавливает процессы `face@<slug>`. Юниты и порядок установки — в
[deploy/README.md](deploy/README.md). Рабочий сервер обновляется автоматически
при `git push` в `main` ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)).

## Устройство репозитория

```
src/main/java/com/facepanel/   панель: controller, service, repository, model, dto, config
src/main/resources/templates/  страницы Thymeleaf
OpenCVRework/face_2.py         точка входа клиента камеры
OpenCVRework/facecore/         логика клиента: capture, pipeline, faces_db, stream, esp, backend
OpenCVRework/supervisor.py     супервизор камер для systemd
deploy/systemd/                юниты для сервера
docker-compose.yml             PostgreSQL для локального запуска
```

`launcher.py`, `launcher.bat` и `LAUNCHER_README.md` — устаревший графический
лаунчер; он ссылается на скрипты, которых больше нет, и для запуска не используется.
